# Prior Calibration With Degree-Aware Weighted Radial Priors

This note explains how the prior calibration works in the full-spectrum
paper-demo code now that the weighted radial prior is degree-aware.

The key point is:

The *shape* of the radial covariance is fixed first, and the calibration then
chooses only a scalar amplitude per physical component and spherical-harmonic
degree.

So the calibration does **not** try to tune the detailed covariance operator
itself. It only decides how large the prior samples should be.

## 1. What is being calibrated?

The model is split into blocks indexed by spherical-harmonic degree and
component:

```math
b = (s,t), \qquad p \in \{\mathrm{vp}, \mathrm{vs}, \rho\}.
```

For `vp` and `rho`, the prior produces a random radial field in each block.
For `vs`, the model-space implementation is split into `vs_IC` and `vs_M`
because the outer core has no shear velocity, but calibration treats those two
pieces as one physical field. The full reconstructed 3-D field is then

```math
f_p(r,\omega)
=
\sum_{s \in \mathcal S}
\sum_{t=0}^{2s}
m_{p,s,t}(r)\,Y_{s,t}(\omega),
```

where:

- `m_{p,s,t}(r)` is the radial coefficient for block `(s,t)`,
- `Y_{s,t}` is the real spherical-harmonic basis function,
- `\mathcal S` is the set of even degrees up to `s_max`.

The calibration chooses the amplitudes `tau_{p,s}` so that reconstructed prior
samples have a chosen target size, usually a target quantile of the maximum
absolute value of the field. For `vs`, that maximum is computed jointly across
the two active radial pieces:

```math
\max |f_{\mathrm{vs}}|
=
\max\left(
  \max_{r \le r_{\mathrm{ICB}},\omega}|f_{\mathrm{vs,IC}}(r,\omega)|,
  \max_{r \ge r_{\mathrm{CMB}},\omega}|f_{\mathrm{vs,M}}(r,\omega)|
\right).
```

## 2. The weighted prior structure

In the weighted case, the radial covariance depends on the spherical-harmonic
degree `s`.

That means the reference covariance is not just one operator per component.
It is one operator per `(component, degree)` pair:

```math
C^{\mathrm{ref}}_{p,s}.
```

The code builds these with the radial Laplacian using `\ell = s`, while
keeping the radial hyperparameters `k`, `\alpha`, and the Sobolev order fixed
across all blocks.

So the prior for a single block is

```math
m_{p,s,t} \sim \mathcal N\!\left(0, \tau_{p,s}^2 \, C^{\mathrm{ref}}_{p,s}\right).
```

Only the scalar `\tau_{p,s}` is calibrated. In the split `vs` case, the
implementation still stores separate `vs_IC` and `vs_M` tau tables for the
prior builder, but both tables come from the same jointly calibrated `vs`
amplitude scale. Before that shared scale is estimated, each split `vs` radial
reference block is normalized by its own pointwise reference standard-deviation
scale. This prevents the `s=0` inner-core Neumann zero mode from dominating the
joint maximum and artificially suppressing the mantle monopole.

## 3. Degree spectrum factorisation

The calibration uses a simple degree spectrum

```math
w_s = (1+s)^{-\beta},
```

with `\beta \ge 0`.

The final calibrated amplitude is written as

```math
\tau_{p,s} = a_p\,w_s,
```

where:

- `w_s` is the chosen degree decay,
- `a_p` is one scalar scale factor for component `p`.

This is important because it keeps the degree behaviour simple and physically
interpretable:

- `\beta = 0` gives no degree decay,
- larger `\beta` suppresses higher degrees more strongly.

The calibration only chooses `a_p`. The degree decay is fixed by `\beta`.

## 4. Why one scalar scale is enough

The prior samples are generated by a linear recipe.
If every `\tau_{p,s}` is multiplied by the same constant `c`, then the entire
reconstructed field is multiplied by `c` as well.

So if `M_p` is the maximum absolute value of a reconstructed prior sample for
component `p`, then

```math
\max_{r,\omega} |f_p(r,\omega)| = c\,M_p
```

whenever all `\tau_{p,s}` are scaled by `c`.

That gives the basic calibration rule:

```math
c = \frac{A_p}{Q_q(M_p)},
```

where:

- `A_p` is the target amplitude for component `p`,
- `Q_q(M_p)` is the `q`-quantile of the Monte Carlo sample maxima.

Then

```math
\tau_{p,s} = c\,(1+s)^{-\beta}.
```

This is why the algorithm can calibrate a complicated degree-aware prior using
one scalar per component.

## 5. What the code actually samples

For each scalar physical component `p`, the code does the following.

1. Build a radial grid `r_i` for that component.
2. Build an angular latitude-longitude grid `(lat_j, lon_k)`.
3. Evaluate the real spherical-harmonic basis matrix `Y` on that angular grid.
4. For each degree `s`, build a radial synthesis matrix from the shared
   degree-specific covariance:

   ```math
   R_{p,s}(i,n) = \sqrt{\lambda_{p,s,n}}\,\phi_{p,s,n}(r_i),
   ```

   where `\lambda_{p,s,n}` and `\phi_{p,s,n}` are the eigenpairs of the
   reference covariance operator.
5. Draw standard normal coefficients `\xi_{s,t,n}`.
6. Form each block contribution

   ```math
   m_{p,s,t}(r_i) = \sum_n R_{p,s}(i,n)\,\xi_{s,t,n}.
   ```
7. Multiply that block by the degree weight `w_s`.
8. Sum over all `(s,t)` blocks and evaluate the field on the tensor grid.
9. Record the maximum absolute value on the grid.

This is repeated many times with Monte Carlo sampling. For `vs`, the same
Monte Carlo draw samples both split radial pieces and records one maximum per
draw by taking the maximum over the inner-core and mantle subdomains.

The code then computes the empirical `q`-quantile of the maxima.

## 6. The calibration equation

Let `M_p^{unit}` be the random maximum absolute value obtained with the
*unit-scale* prior, meaning `a_p = 1`.

Then the calibrated scale is

```math
a_p = \frac{A_p}{Q_q(M_p^{unit})}.
```

After that,

```math
\tau_{p,s} = a_p (1+s)^{-\beta}.
```

This is the main calibration formula used by the code.

## 7. Why the weighted case is more complicated than the flat case

In the older flat setup, every component used one shared radial covariance
operator, so the only thing that changed was the scalar `\tau_{p,s}`.

In the weighted setup, the covariance operator itself depends on the degree:

```math
C^{\mathrm{ref}}_{p,s} \neq C^{\mathrm{ref}}_{p,s'} \quad \text{if } s \neq s'.
```

That means there is now an extra layer:

- first choose the degree-specific covariance shape,
- then scale it by `\tau_{p,s}`.

Even so, the calibration logic stays simple because all of those covariance
operators are treated as fixed during the calibration run.

## 8. Algorithmic summary

In words, the algorithm is:

1. Decide which blocks `(s,t)` are present.
2. Build the degree-aware weighted radial covariance operators.
3. Choose the degree decay exponent `\beta`.
4. Sample the reconstructed prior field many times with `a_p = 1`.
5. Measure the quantile of the maximum absolute field amplitude.
6. For split `vs`, measure this maximum jointly over `vs_IC` and `vs_M`.
7. Rescale by `A_p / Q_q`.
8. Store `\tau_{p,s}` for use by the prior builder and the tuner app.

The tuner app uses those values automatically when the user clicks
`Build Prior`.

## 9. What does not get calibrated here?

This calibration does **not** tune:

- the radial Laplacian parameter `k`,
- the radial stiffness `\alpha`,
- the Sobolev order,
- the boundary conditions.

Those are treated as fixed hyperparameters.

If any of them change, the calibration should be rerun because the reference
covariance shape changes and the unit-quantile `Q_q(M_p^{unit})` will change.

## 10. Practical interpretation

If the target amplitude is, say, `0.05`, then the prior is being calibrated so
that a typical reconstructed prior field has a maximum size around that level
in the chosen quantile sense.

If the calibrated `\tau_{p,s}` values are too small, the prior becomes overly
concentrated and the samples look too flat.

If they are too large, the samples become unrealistically rough or too large in
amplitude.

The Monte Carlo step is what connects the abstract covariance operator to a
field amplitude that is easy to interpret physically.
